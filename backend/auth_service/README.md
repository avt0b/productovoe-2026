# auth_service

Сервис аутентификации платформы «Маршруты победы». Вход по **email + паролю**,
выдача и ротация JWT.

## Запуск

```bash
uv sync
cp .env.example .env          # при необходимости поправьте JWT_SECRET / DATABASE_URL
uv run uvicorn main:app --reload --port 8001
```

Swagger — <http://127.0.0.1:8001/docs>.

По умолчанию `DATABASE_URL` указывает на PostgreSQL. Для быстрого локального
прогона можно временно поставить `DATABASE_URL=sqlite+pysqlite:///./auth.sqlite`.
Схема создаётся на старте (`init_db`), миграции alembic — задел на потом.

## Тесты

```bash
uv run pytest          # sqlite во временном файле, Postgres не нужен
uv run ruff check .
```

## Архитектура (3 слоя)

```
api/           # HTTP-слой: роутеры + pydantic-схемы валидации + deps
  routers/     #   auth.py (register/login/refresh/logout/me), admin.py (is_root)
  schemas/     #   auth.py, user.py
  deps.py      #   get_db, фабрики сервисов, get_current_user, require_root
services/      # бизнес-логика: AuthService, UserAdminService, bootstrap
repositories/  # доступ к БД: UserRepository, RefreshTokenRepository
core/          # config, db (инициализация), security, exceptions, models/
main.py        # сборка FastAPI, обработчик доменных ошибок, lifespan
```

Правило слоёв: роутер парсит запрос и вызывает сервис; сервис оркеструет
репозитории и владеет транзакцией (`commit`); репозиторий делает только SQL.
Доменные ошибки (`core/exceptions.py`) сервис бросает как есть — `main.py`
превращает их в HTTP-ответ.

## Модель авторизации

- **Токен:** JWT **HS256** с общим секретом `JWT_SECRET` (тот же секрет у
  остальных сервисов — проверяют подпись локально, без вызова auth).
  Прод-апгрейд — RS256 с приватным ключом только здесь.
- **Пара токенов:** `access` (~15 мин, в нём `sub`, `role`, `is_root`) +
  `refresh` (~30 дней). В БД хранится только SHA-256 хэш refresh-токена.
  При `/auth/refresh` — ротация; повторное использование старого токена
  трактуется как компрометация и отзывает всю цепочку сессий пользователя.
- **Пароли:** Argon2id (`argon2-cffi`), прозрачный re-hash при смене параметров.
- **`role`** — Enum (`family` / `searcher` / `local_historian` / `mentor` /
  `moderator`), задаётся при регистрации, меняется только из админки.
- **`is_root`** — отдельный булев флаг доступа в админку, не роль. Первый
  администратор создаётся на старте из `BOOTSTRAP_ROOT_EMAIL` / `_PASSWORD`.

## Эндпоинты

| Метод и путь                      | Доступ            | Назначение                          |
| --------------------------------- | ----------------- | ----------------------------------- |
| `POST /auth/register`             | публично          | регистрация (email, пароль, роль)   |
| `POST /auth/login`                | публично          | выдача пары токенов                 |
| `POST /auth/refresh`              | refresh-токен     | ротация пары токенов                |
| `POST /auth/logout`               | refresh-токен     | отзыв refresh-токена                |
| `GET  /auth/me`                   | access-токен      | текущий пользователь                |
| `POST /auth/change-password`      | access-токен      | смена пароля + разлогин всех сессий |
| `GET  /admin/users`               | `is_root`         | список пользователей                |
| `PATCH /admin/users/{id}/role`    | `is_root`         | сменить роль                        |
| `PATCH /admin/users/{id}/active`  | `is_root`         | включить/отключить учётку           |
| `PATCH /admin/users/{id}/root`    | `is_root`         | выдать/снять доступ в админку       |

## Вход через VK ID, MAX и Госуслуги

Одна схема на всех провайдеров, токены никогда не попадают в URL.

1. **Приложение начинает вход** — `POST /auth/external/{vk|max|gosuslugi}/start`
   с `return_to` (адрес возврата в приложение, например `marshruty://auth/external`).
   Ответ — `login_id` (секрет попытки, хранится в приложении) и `authorize_url`.
2. **Человек подтверждает вход у провайдера.**
   - **VK ID и Госуслуги** — `authorize_url` открывается в браузере, провайдер
     возвращает человека на `GET /auth/external/{provider}/callback`, а оттуда —
     в `return_to?provider=...&result_code=...` (или `&error=...`).
   - **MAX** — `authorize_url` ведёт на бота мессенджера со стартовым payload.
     Мессенджер присылает `POST /auth/external/max/webhook`, и попытка
     подтверждается.
3. **Приложение забирает токены** — `POST /auth/external/complete` с `login_id` и,
   после редиректа, `result_code`. Пока вход не подтверждён — `202 pending`,
   приложение повторяет запрос раз в пару секунд. Ответ — та же пара токенов,
   что у `/auth/login`, плюс пользователь, `display_name` от провайдера и
   `is_new_user`.

`GET /auth/external/providers` — какие кнопки показывать: провайдер настроен или
включён тестовый режим.

### Почему так

- **`result_code` приходит только на устройство, где человек подтвердил вход.**
  Кто пришлёт другому свою ссылку входа, токенов не получит: у него есть
  `login_id`, но нет кода.
- **Новые пользователи получают роль «семья» и служебную почту**
  `vk-<id>@external.marshruty.ru`. Почта у пользователя обязательна (вход по
  паролю, админка, приложение), пароль — случайный и никому не известный.
- **К существующему аккаунту по почте от провайдера не привязываем** — иначе
  чужой аккаунт с той же почтой можно было бы угнать. Повторный вход тем же
  аккаунтом VK или MAX попадает в того же пользователя (`external_identities`).
- **`return_to` — только адреса приложения** (`EXTERNAL_AUTH_RETURN_PREFIXES`),
  иначе callback стал бы открытым редиректом.
- **Попытка живёт 10 минут и выдаёт токены один раз.**

### Что нужно, чтобы включить по-настоящему

| Провайдер | Состояние | Что нужно |
| --- | --- | --- |
| **VK ID** | готов, OAuth 2.1 + PKCE | приложение на id.vk.com → `VK_ID_CLIENT_ID`, redirect `<EXTERNAL_AUTH_PUBLIC_URL>/auth/external/vk/callback`; адреса ручек VK ID вынесены в настройки — сверить с документацией |
| **MAX** | готов, вход через бота | публичного OAuth у MAX нет. Нужен бот на платформе MAX (только верифицированное российское юрлицо) → `MAX_BOT_NAME`, `MAX_WEBHOOK_SECRET`. Форма обновления бота разбирается терпимо — сверить с dev.max.ru. У бота нет редиректа на устройство, поэтому ссылку на бота нельзя пересылать; бот должен прямо спрашивать «Войти в Маршруты победы?» |
| **Госуслуги** | заготовка, отвечает 503 | ЕСИА подключает только зарегистрированную систему юрлица: учётная запись организации, ключ и сертификат, подпись запросов по ГОСТ, проверка в тестовой среде. Когда будет — реализовать `authorize_url` и `exchange` в `services/external/gosuslugi.py`, ручки не меняются |

### Тестовый режим

`EXTERNAL_AUTH_MOCK=true` (в `.env.example` включён): провайдеры, которые не
настроены, заменяются страницей «Тестовый вход через …» с полем имени. Весь
путь — callback, `result_code`, токены — проходится локально без ключей и
юрлица. При `APP_ENV=production` тестовый режим не работает.
