# media_service

«Живое фото» (модуль 7 ТЗ): пользователь загружает фотографию бойца, сервис
ставит задачу на генеративное оживление (NeRF / face reenactment / lip-sync),
готовый ролик (15–30 сек) попадает в семейный архив и/или общий мемориал.

**Этическая оговорка ТЗ:** технология — только для мемориальных целей, с
уважением к памяти; коммерческое использование и изменение смысла запрещены.
На уровне API это `consent_memorial_use`: поле необязательно в схеме
(дефолт `false`), но заявка без явного `true` всегда отклоняется одинаковым
`403` — что поле не прислали, что прислали `false`, роли не играет.

## Запуск

```bash
uv sync
cp .env.example .env          # JWT_SECRET = как в auth_service; DATABASE_URL -> БД media
uv run uvicorn main:app --reload --port 8007
```

Swagger — <http://127.0.0.1:8007/docs>. Тесты: `uv run pytest`.

## Что реализовано (MVP)

Полный жизненный цикл заявки и мемориала, загрузка исходного фото в MinIO,
связь с точкой на карте. Сервис хранит только состояние заявки и переходы
(`queued` → `processing` → `ready` / `failed`) — саму генерацию видео делает
внешний воркер, [media_render_worker](../media_render_worker/) (Yandex
SpeechKit для голоса + Replicate/SadTalker для липсинка), через `/render/*`.
Без поднятого воркера (или без ключей у него в `.env`) заявки копятся в
`queued`/улетают в `failed` — сам `media_service` от этого не страдает.

`MemorialClip`: `soldier_name`, `source_photo_url` (загружается через
`/uploads`), `narration_text` (текст от первого лица), `voice_style`,
`consent_memorial_use`, `is_public`, `status`, `video_url`,
`archive_entry_id` (связь с карточкой бойца в `archive_service`), `poi_id`
(связь с точкой слоя «ВОВ» в `map_service` — памятником или братской
могилой, у которой предложено «оживить» фото неизвестного бойца).

Если `narration_text` не передан явно, а `archive_entry_id` указан —
`ClipService.create` (`services/archive_client.py`) сам сходит в
archive_service за подтверждённой карточкой бойца и допишет к дефолтному
монологу краткую версию подвига из её `body` (п.7 ТЗ: «боец может рассказать
краткую версию своего подвига — берётся из базы подвига»). Не нашли/не
ответили — остаётся только дефолтный монолог, заявка всё равно создаётся.

`ClipShare` — кнопка «Отправить родным» (кому, заметка).

## Эндпоинты

| Метод | Путь | Доступ |
| --- | --- | --- |
| GET | `/clips` `?poi_id` | публично — общий мемориал (`ready` + `is_public`) |
| GET | `/clips/mine` `?status` | автор |
| POST | `/clips` | любой авторизованный (нужен `consent_memorial_use=true`) |
| GET | `/clips/{id}` | публичный готовый — все; иначе автор / модератор |
| PATCH | `/clips/{id}` | автор (текст/голос/публичность, пока не в работе) |
| POST | `/clips/{id}/retry` | автор — перезапуск после `failed` |
| DELETE | `/clips/{id}` | автор / модератор |
| POST | `/clips/{id}/shares` · GET | автор — «Отправить родным» (клип должен быть `ready`) — см. ограничение в «Дальше» |
| POST | `/uploads` | любой авторизованный — файл → MinIO, возвращает `url` (см. ниже) |
| POST | `/render/claim` | воркер (`X-Worker-Token`) или модератор — взять из очереди |
| POST | `/render/{id}/ready` · `/failed` | воркер или модератор |

### Загрузка файлов (`POST /uploads`)

Общая ручка на всё приложение: исходное фото бойца для «Живого фото», фото и
аудиовоспоминания к записям «Живой памяти» (модуль 6 ТЗ), фото героев семьи.

| Тип | Content-Type | Лимит |
| --- | --- | --- |
| Фото | `image/jpeg`, `image/png`, `image/webp` | 15 МБ |
| Аудио | `audio/mpeg`, `audio/ogg`, `audio/wav` (`audio/x-wav`, `audio/wave`), `audio/mp4` (`audio/x-m4a`), `audio/webm` | 30 МБ |

Остальное — `415`, больше лимита — `413`. Расширение ключа в MinIO берётся из
имени файла (`voice.mp3` → `<user_id>/<uuid>.mp3`).

## Дальше

- **«Отправить родным» — только журнал намерения, не доставка.** `recipient`
  в `POST /clips/{id}/shares` — произвольная строка, которую вводит сам
  пользователь; поиска потомков бойца через соцсети или поисковый отряд, как
  описано в кейсе («если найдены потомки через соцсети или поисковый
  отряд»), нет и не может быть чисто бэкенд-фиксом без внешней интеграции
  (VK API и т.п.) — оставлено как есть, не в scope текущих правок.
- Синтез речи «с патиной радиосвязи», подбор голоса эпохи — сейчас
  `media_render_worker` берёт голос по `voice_style` один в один из
  SpeechKit, без пост-обработки под «радиосвязь».
- Модерация публичных клипов перед попаданием в общий мемориал.
