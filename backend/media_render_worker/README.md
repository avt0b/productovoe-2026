# media_render_worker

Воркер рендера «Живого фото» (модуль 7 ТЗ) — тот самый «главный оставшийся
долг», про который `media_service/README.md` пишет: «реальная генерация
видео... остаётся за внешним воркером». Это и есть внешний воркер.

**Не FastAPI-сервис** — не слушает порт, не входит в таблицу сервисов
`backend/README.md`. Обычный Python-процесс с бесконечным циклом опроса.

## Что делает

Раз в `POLL_INTERVAL_SECONDS` спрашивает у `media_service`, есть ли в
очереди клип (`POST /render/claim`, `queued -> processing`).

Оживляет один из двух провайдеров (`RENDER_PROVIDER`, по умолчанию `auto`):

- **Ranvik — беззвучно, 5 секунд** (`clients/ranvik.py`), если задан
  `RANVIK_API_KEY`. Seedance 1.5 Pro по фото: боец моргает, дышит, чуть
  улыбается и поворачивает голову; звук и движение камеры выключены. Фото
  уходит в запросе `data:` URI, ролик скачивается с CDN Ranvik сразу (он
  хранит его сутки). Голос не нужен — цитата бойца в приложении и так
  подписана поверх ролика.
- **SpeechKit + Replicate — голос и липсинк**, если ключа Ranvik нет:


1. **Yandex SpeechKit** — озвучивает `narration_text` голосом по
   `voice_style` (`clients/speechkit.py`).
2. **Replicate (SadTalker)** — анимирует фото под получившееся аудио,
   липсинк по звуку, а не по текстовому промпту (`clients/lipsync.py`).
   Фото своё берётся из бакета по ключу, а не по ссылке из заявки
   (`storage.fetch_source`): в ссылке — IP компьютера на момент загрузки,
   он меняется вместе с сетью. Pillow разворачивает его по EXIF и ужимает до
   768 px (`services/photo.py`). `preprocess=full` — в кадре вся фотография,
   а не кроп лица 256×256.
3. Готовый ролик перезаливает в MinIO (`services/storage.py`, тот же бакет
   `media`, что у `media_service`).
4. Сообщает результат обратно: `POST /render/{id}/ready` с `video_url`, или
   `/failed` с текстом ошибки — тем же токеном, каким брал клип в работу.
   Текст — объяснение для автора (`core/errors.py`): «SpeechKit: ключ не
   принят», «Replicate: на счёте нет средств», «На фото не нашлось лица».
   Без любого из четырёх ключей рендер не начинается вовсе — заявка сразу
   уходит в `failed` с «нет ключей». Любая неожиданная ошибка тоже отпускает
   клип в `failed`, а не оставляет его в `processing`.

### Ranvik — `RANVIK_API_KEY`

Агрегатор нейросетей с оплатой в рублях — зарубежная карта не нужна.

1. Войти через Ranvik ID на [api.ranvik.ru](https://api.ranvik.ru).
2. Пополнить баланс (от 50 ₽).
3. Кабинет → **API-ключи** → создать ключ `rk_live_…` → в `RANVIK_API_KEY`.

Цена — Seedance 1.5 Pro, 720p без звука: 3,43 ₽ за секунду, ролик на 5
секунд — около 17 ₽ (480p — вдвое дешевле: `RANVIK_RESOLUTION=480p`).
Модель и длительность — `RANVIK_MODEL`, `RANVIK_DURATION_SECONDS`.

## Запуск (локально)

```bash
uv sync
cp .env.example .env    # см. «Что нужно от DevOps» — без ключей просто не будет работать
uv run python main.py
```

Тесты: `uv run pytest` (моки на границе, реальных ключей не требуют).
Линт: `uv run ruff check .`

## Что нужно от DevOps

Без этих четырёх значений в `.env` (или в общем `.env` на VPS — секция
«Живое фото» в корневом `.env.example`) воркер не запустится содержательно:
`RENDER_WORKER_TOKEN` совпадёт с пустым дефолтом только случайно, а без
Yandex/Replicate ключей любой клип будет улетать сразу в `failed`.

### 1. `RENDER_WORKER_TOKEN`

Не регистрация — просто общий секрет. Сгенерировать любую случайную строку
и прописать **одинаковое значение в двух местах**: `media_render_worker/.env`
и `media_service/.env` (или один раз в корневом `.env` на VPS — обе службы
берут его оттуда через `docker-compose.yml`). Не совпадёт — воркер получит
`403` на каждый вызов `/render/*`.

### 2. Yandex Cloud — `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`

Синтез речи (SpeechKit) — те же голосовые модели, что говорят голосом Алисы.

1. Завести аккаунт на [cloud.yandex.ru](https://cloud.yandex.ru) (понадобится
   привязать карту — есть бесплатный грант, но без карты не пускают).
2. В консоли выбрать/создать **каталог** (folder) — его id и есть
   `YANDEX_FOLDER_ID` (виден в адресной строке консоли или на странице
   каталога).
3. **Identity and Access Management → Сервисные аккаунты → Создать
   сервисный аккаунт.**
4. Аккаунту назначить роль **`ai.speechkit-tts.user`** (именно
   text-to-speech, не распознавание).
5. У этого сервисного аккаунта: вкладка **API-ключи → Создать API-ключ**.
   Значение показывается один раз — сразу в `YANDEX_API_KEY`.

Цена ориентировочно ~1342 ₽ за 1 млн символов (API v1, синтез) — для
монолога на 15–30 сек это доли копейки за клип.

### 3. Replicate — `REPLICATE_API_TOKEN`, `REPLICATE_MODEL_VERSION`

Липсинк-модель (SadTalker) — считает на их GPU, свой сервер не нужен.

1. Завести аккаунт на [replicate.com](https://replicate.com) (вход хоть
   через GitHub), привязать способ оплаты — тарификация по факту запуска,
   без обязательной подписки.
2. **Account settings → API tokens → Create token** → в `REPLICATE_API_TOKEN`.
3. Открыть страницу модели (например
   [replicate.com/cjwbw/sadtalker](https://replicate.com/cjwbw/sadtalker)),
   вкладка **API** — там указана точная версия вида `owner/model:hash`.
   Это целиком идёт в `REPLICATE_MODEL_VERSION`. Версия — конкретный
   зафиксированный слепок модели; сама молча не обновляется, менять руками,
   осознанно. Хэш — ровно 64 символа: обрезанный Replicate не найдёт.
   Проверенная версия (2024-06-01):
   `cjwbw/sadtalker:a519cc0cfebaaeade068b23899165a11ec76aaa1d2b313d40d214f204ec957a3`.
4. **На счёте должны быть деньги.** Без них создание прогона отвечает
   `402 insufficient credit` — заявка уходит в `failed` с «на счёте нет
   средств». После пополнения Replicate просит подождать пару минут.

Цена — по факту прогона, у SadTalker ориентировочно $0.09–0.16 за клип
(зависит от того, какую версию модели выбрали).

## Почему так, а не иначе

- **SpeechKit + Replicate, а не один комбайн (D-ID и т.п.).** Разделили
  голос и липсинк на два конкретных инструмента: SpeechKit звучит по-русски
  естественнее (та же модель, что у Алисы), Replicate — на порядок дешевле
  D-ID за минуту видео и не требует месячной подписки. Подробное сравнение
  вариантов и цен обсуждалось в чате при выборе, тут — уже решение.
- **SpeechKit отдаёт «голый» LPCM без WAV-заголовка** (`format=lpcm`) — заголовок
  дописывает сам `clients/speechkit.py` модулем `wave`, чтобы Replicate
  однозначно распознал файл как аудио, не полагаясь на угадывание по
  содержимому.
- **Фото и голос — через Files API Replicate, не ссылками на MinIO.** На
  стенде MinIO живёт на IP в локальной сети — Replicate до него не достанет;
  `data:` URI он берёт только до 256 КБ, а голос на 48 кГц — ~100 КБ в
  секунду. После прогона оба файла удаляются, прогону ставится `Cancel-After`
  на `RENDER_TIMEOUT_SECONDS` (900 сек: холодный старт модели — минуты) —
  брошенный рендер Replicate отменит сам и не выставит за него счёт.
- **Свой `User-Agent`.** API Replicate стоит за Cloudflare, стандартный
  Python-urllib он режет с 403 (код 1010).
- **Без очереди с повторами.** Как и у остальных внутрисервисных вызовов
  в проекте — ошибка форвардится в `failed`, автор жмёт «Повторить»
  (`POST /clips/{id}/retry` в `media_service`) сам.

## Дальше

- **Если `mark_failed` сам не дойдёт** (сеть отвалилась именно на этом шаге)
  — клип зависает в `processing` навсегда: `retry` в `media_service` работает
  только из `failed`, восстановления для «завис в processing» нет. Известное
  ограничение, не баг.
- **Гонка при `claim_next`, если запустить больше одного воркера.**
  `ClipRepository.oldest_queued()` не блокирует строку (`SELECT ... FOR
  UPDATE`) — два воркера теоретически могут взять один клип и оба его
  обработать (задвоенная оплата Replicate, не порча данных: кто вызвал
  `ready`/`failed` последним, тот и победил). Пока рассчитан ровно на один
  инстанс — в `docker-compose.yml` так и заведено, без `replicas`.
- Ретраи с бэк-оффом на сетевые сбои — сейчас одна попытка на клип.
