# admin_service

Панель администратора платформы «Маршруты победы». Веб-приложение (Vue) ходит
только сюда: собственная аутентификация с TOTP, сводный дашборд по всем
сервисам, операции над данными и неизменяемый журнал аудита.

## Запуск

```bash
uv sync
cp .env.example .env   # обязательно поменяйте ADMIN_JWT_SECRET и INTERNAL_API_KEY
uv run uvicorn main:app --reload --port 8010
```

Swagger — <http://127.0.0.1:8010/docs>.

Для локального прогона без Postgres можно временно поставить
`DATABASE_URL=sqlite+pysqlite:///./admin.sqlite`.

## Тесты

```bash
uv run pytest        # sqlite во временном файле, соседние сервисы не нужны
uv run ruff check .
```

## Модель доступа — почему отдельная от `auth_service`

Админка **не** принимает пользовательские токены, а пользовательские сервисы
не принимают токен админки. Разные секреты (`ADMIN_JWT_SECRET` против общего
`JWT_SECRET`) и разные issuer — утечка одного контура не открывает второй.

- **Пароли:** Argon2id, прозрачный re-hash при смене параметров.
- **Вход в два шага:** `/login` (email + пароль) → при включённой 2FA отдаёт
  только короткоживущий `mfa_token`, который меняется на пару токенов в
  `/login/mfa`. Сам `mfa_token` не даёт доступа ни к чему.
- **TOTP** (RFC 6238, `pyotp`): `/totp/setup` выдаёт секрет и `otpauth://`-ссылку
  (QR рисует фронт), `/totp/confirm` включает 2FA и возвращает 10 кодов
  восстановления — они показываются **один раз** и хранятся только хэшами.
- **`REQUIRE_TOTP=true`** (по умолчанию): администратор без настроенного TOTP
  доходит только до `/admin/auth/*`, то есть ровно до настройки второго фактора.
- **Токены:** `access` ~30 мин (в нём `sub`, `email`, `role`, `amr`),
  `refresh` 7 дней с ротацией. Повторное использование отозванного
  refresh-токена трактуется как компрометация и гасит все сессии.
- **Перебор пароля:** после `MAX_FAILED_ATTEMPTS` неудач учётка блокируется на
  `LOCKOUT_MINUTES`. Несуществующий email отвечает тем же 401 и с тем же
  временем ответа, что и неверный пароль.

### Роли внутри админки

| Роль         | Что может                                                |
| ------------ | -------------------------------------------------------- |
| `superadmin` | всё + управление учётками администраторов                 |
| `admin`      | операции над пользователями и контентом                   |
| `moderator`  | модерация контента                                        |
| `viewer`     | только чтение: дашборд, списки, журнал аудита             |

Это роли **администраторов**, они не пересекаются с ролями пользователей
платформы (`family` / `searcher` / `local_historian` / …).

## Как админка ходит в данные

Своей копии данных у админки нет. Она вызывает служебную плоскость
`/internal/*` каждого сервиса:

```
admin_service ──X-Internal-Key + X-Actor-Id──► auth / user / map / route /
                                               search_hq / archive / media
```

- **`X-Internal-Key`** — общий секрет (`INTERNAL_API_KEY`). Наружу `/internal/*`
  не публикуется: закрывается на reverse proxy.
- **`X-Actor-Id`** — id администратора. Сервис строит из него `Principal` с
  максимальными правами, поэтому бизнес-правила (например, «нельзя опубликовать
  маршрут без точек») продолжают работать, а в `created_by` / `verified_by`
  оседает настоящий актор.

Политику «кому что можно» держит админка, данные — сервисы-владельцы.

## Эндпоинты

### Аутентификация — `/admin/auth`

| Метод и путь            | Назначение                                     |
| ----------------------- | ---------------------------------------------- |
| `POST /login`           | шаг 1: email + пароль                          |
| `POST /login/mfa`       | шаг 2: код из приложения или код восстановления |
| `POST /refresh`         | ротация пары токенов                           |
| `POST /logout`          | отзыв refresh-токена                           |
| `POST /logout-everywhere` | завершить все сессии                         |
| `GET  /me`              | текущий администратор + состояние 2FA          |
| `POST /change-password` | смена пароля (гасит все сессии)                |
| `POST /totp/setup`      | секрет и `otpauth://` для QR                   |
| `POST /totp/confirm`    | включить 2FA, получить коды восстановления     |
| `POST /totp/disable`    | отключить 2FA (нужны пароль и код)             |
| `POST /totp/recovery-codes` | перевыпустить коды восстановления          |

### Дашборд — `/admin/dashboard`

| Метод и путь    | Назначение                                          |
| --------------- | --------------------------------------------------- |
| `GET /overview` | 6 плиток KPI, сводка, состояние сервисов, хвост журнала |
| `GET /timeseries` | ряды за N дней для графика                        |
| `GET /health`   | доступность всех сервисов платформы                 |

Недоступный сервис не роняет дашборд: его плитки приходят с `null`, а имя
попадает в `degraded` — фронт рисует прочерк.

### Операции — `/admin/ops`

Пользователи и роли, профили и верификация статуса, модерация архива, точки
«Последнего боя», отряды, сборы, выезды, маршруты, «Живое фото». Каждое
изменяющее действие пишет строку в журнал аудита. Роль `viewer` изменять
ничего не может.

### Учётки администраторов — `/admin/accounts` (только `superadmin`)

Создание, смена роли, включение/отключение, сброс пароля, снятие 2FA, удаление.
Последнего активного суперадминистратора отключить или понизить нельзя.

### Журнал аудита — `/admin/audit`

Только чтение с фильтрами (автор, действие, сервис, период, поиск). Записи
неизменяемы — API на правку и удаление намеренно нет: должно быть видно, кто
и на каком основании поправил данные о погибшем.

## Архитектура

```
api/           # HTTP: роутеры (auth, dashboard, operations, accounts, audit),
               #       схемы, deps (аутентификация и проверка ролей)
services/      # AdminAuthService, AccountService, AuditService,
               # DashboardService (сведение плиток), Upstream (клиент /internal)
repositories/  # AdminRepository, SessionRepository, AuditRepository
core/          # config, db, security (argon2 + JWT + TOTP), exceptions, models/
main.py        # сборка FastAPI, CORS, обработчик доменных ошибок, lifespan
```

## Известные компромиссы

- Роутеры `dashboard` и `operations` — `async` (нужен веерный опрос семи
  сервисов через `asyncio.gather`), но запись в журнал аудита идёт синхронным
  SQLAlchemy. На нагрузке админки это незаметно; при переезде на прод стоит
  вынести аудит в async-сессию или в очередь.
- Схема создаётся через `create_all`, миграции alembic — задел на потом.

## Дальше

Макет админки требует ещё трёх вещей, которых в бэкенде пока нет:

1. **«Источники и импорт»** — сервис пакетного импорта Книг Памяти (найдено /
   привязано / к краеведам / дубли, прогресс, ошибки парсинга). Дашборд уже
   отдаёт его в поле `not_implemented`.
2. **Наградной комитет** — знаки, баллы и рейтинг участников; логичное место —
   `user_service` рядом с достижениями.
3. **Бан со сроком** — сейчас в `auth_service` только булев `is_active`;
   для «7 / 30 дней / бессрочно» нужны `banned_until` и причина.
