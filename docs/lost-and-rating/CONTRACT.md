# Контракт: «Я потерялся» и рейтинг краеведов

Единственный источник правды для двух сторон:

- **бэкенд** (`search_hq_service`, немного `user_service`) — задание в [BACKEND.md](./BACKEND.md);
- **мобилка** (`frontend/client`) — задание в [MOBILE.md](./MOBILE.md).

Всё, что здесь написано, бэкенд обязан отдавать ровно так, а мобилка может на
это рассчитывать. Нужно что-то поменять (поле, код ошибки, текст) — сначала
правка этого файла отдельным PR в `develop`, обе стороны её видят, потом код.
Молча расходиться с контрактом нельзя.

---

## 0. Общие правила

**Адреса.** Все ручки ниже — относительно корня сервиса.

| Сервис | В мобилке (`ServiceName`) | Прод | Локально |
|---|---|---|---|
| `search_hq_service` | `'hq'` | `https://marshrutpobedy.website/api/search` | `http://127.0.0.1:8004` |
| `user_service` | `'users'` | `https://marshrutpobedy.website/api/users` | `http://127.0.0.1:8002` |

**Авторизация.** `Authorization: Bearer <access-JWT из auth_service>`. Ручки с
пометкой «публичная» работают и без токена.

**Ошибки.** Любая ошибка — JSON `{"detail": "Текст для человека"}`. Текст
пишется так, чтобы его можно было показать в приложении как есть. Мобилка
показывает `detail`, а не придумывает свои тексты. Коды: `401` — нет или
просрочен токен, `403` — нельзя этому человеку, `404` — нет такого объекта,
`409` — нельзя сейчас (не то состояние), `422` — кривое тело запроса.

**Время.** ISO 8601 в UTC с `Z`: `"2026-09-26T10:15:03Z"`.

**id.** Строка UUID (`"5f0c7a2e-3b1d-4c55-9a0e-2f4b8e1c9d10"`).

**Уведомления.** Бэкенд кладёт их в `user_service` (`GET /notifications`
отдаёт `{id, kind, title, body, payload, read_at, created_at}`). Пушей сейчас
нет, FCM без ключей: мобилка опрашивает `/notifications` раз в 10 секунд, пока
приложение открыто. Закрытое приложение уведомление не получит. Это
ограничение стенда, а не контракта: с ключами FCM те же уведомления придут
пушем без изменений в ручках.

## 1. «Я потерялся»

### 1.1. Кто есть кто

- **Прогулка** — экскурсия в статусе `walking`: краевед ведёт собранную
  группу, телефоны шлют свои точки (`PUT /excursions/{id}/walk/position`,
  уже есть).
- **Участник группы** — записан на экскурсию (`status = registered`) и
  отметился бампом (`checked_in_at` не `null`). Только участники группы и
  краевед видят карту группы и участвуют в поиске.
- **Потерявшийся** (`lost`) — тот, кого ищут. Всегда участник группы, не краевед.
- **Тот, кто поднял тревогу** (`raised_by`):
  - сам потерявшийся — нажал «Я потерялся», вид тревоги `kind = "self"`;
  - член его семьи из группы или краевед — нажал «Не вижу …», `kind = "reported"`.
- **Ищущие** (`watchers`) — кому пришла тревога:
  - краевед экскурсии (`relation = "guide"`);
  - члены семьи потерявшегося (связь в `family_links`, в обе стороны), которые
    сами участники этой группы (`relation = "family"`).

  Состав ищущих фиксируется в момент тревоги. Если семья в приложении не
  связана, тревога всё равно уходит краеведу.
- **Откликнулся** (`responding = true`) — ищущий нажал «Иду». Тот, кто поднял
  тревогу через «Не вижу …», считается откликнувшимся сразу.

Родные, которых нет в группе (бабушка дома), тревогу **не** получают.

### 1.2. Жизненный цикл

```
            POST /excursions/{id}/lost
                       │
                       ▼
                 ┌──────────┐   POST …/resolve   ┌────────┐
                 │  active  │ ─────────────────▶ │ found  │
                 └──────────┘                    └────────┘
                   │      │     POST …/cancel    ┌───────────┐
                   │      └────────────────────▶ │ cancelled │
                   │                             └───────────┘
                   │  прошло 120 минут или       ┌─────────┐
                   └──── прогулка закрылась ───▶ │ expired │
                         по сроку                └─────────┘
```

Правила:

1. Тревогу можно поднять, только пока экскурсия в статусе `walking`.
2. Для одного человека на одной экскурсии открыта не больше одной тревоги.
   Повторный `POST /excursions/{id}/lost` на того же человека возвращает уже
   открытую (код `200`, без повторной рассылки уведомлений).
3. Пока на экскурсии есть открытая тревога, краевед **не может** завершить
   прогулку (`POST /excursions/{id}/walk/finish`) или отменить экскурсию
   (`POST /excursions/{id}/cancel`): `409` с текстом
   `"Кто-то из группы потерялся — сначала найдите его или закройте поиск"`.
4. Тревога живёт не дольше **120 минут** с момента создания. Потом при первом
   обращении к любой ручке тревог она становится `expired`, без уведомлений.
   Если прогулка закрылась по сроку (через 4 часа после выхода группы), её
   открытые тревоги тоже становятся `expired`.
5. «Нашлись» (`resolve`) может нажать потерявшийся, любой ищущий или
   администратор (`is_root`).
6. «Отбой» (`cancel`, ложная тревога) может нажать потерявшийся, тот, кто
   поднял тревогу, или администратор.
7. Координаты людей — те же, что у прогулки: таблица позиций группы, куда
   пишет `PUT /excursions/{id}/walk/position`. Отдельной ручки координат у
   тревоги нет. В ответе тревоги позиция отдаётся **без** фильтра свежести
   (на карте группы точки старше 2 минут скрываются, а здесь — нет) вместе с
   `updated_at`: «последняя точка 3 минуты назад» лучше, чем ничего.

| Поле | Тип | Что значит |
|---|---|---|
| `status` | `"active" \| "found" \| "cancelled" \| "expired"` | см. 1.2 |
| `kind` | `"self" \| "reported"` | сам нажал «Я потерялся» / другой нажал «Не вижу …» |

| `watchers[].relation` | `"family" \| "guide"` | член семьи или краевед |
| `watchers[].distance_m` | целое или `null` | метры между ищущим и потерявшимся; `null`, если чьей-то точки нет |
| `display_name` | строка | из профиля в `user_service`. Профиля нет или сервис не ответил — `"Участник группы"` (для краеведа — `"Краевед"`) |
| `avatar_url` | строка или `null` | полная ссылка |
| `resolved_by` | `{user_id, display_name}` или `null` | кто нажал «Нашлись» / «Отбой»; для `expired` — `null` |

### 1.4. Ручки

#### `POST /excursions/{excursion_id}/lost` — поднять тревогу

Тело (все поля необязательны, пустое тело `{}` допустимо):

```json
{
  "lost_user_id": null,
  "lat": 53.27912,
  "lon": 36.57518,
  "accuracy_m": 15.0,
  "message": "Я у фонтана"
}
```

- `lost_user_id` не передан, `null` или равен моему id — «Я потерялся».
- `lost_user_id` — чужой id — «Не вижу …»: я краевед экскурсии, администратор
  или участник группы из семьи этого человека.
- `lat`/`lon`/`accuracy_m` — **моя** точка сейчас. Если переданы, бэкенд
  сохраняет её как позицию в группе (как `PUT …/walk/position`), чтобы тревога
  сразу открылась со свежей точкой. `lat` от −90 до 90, `lon` от −180 до 180,
  передаются только вместе.
- `message` — до 200 символов, пробелы по краям обрезаются.

Ответ: `201` и `LostAlert` — новая тревога; `200` и `LostAlert` — на этого
человека уже есть открытая тревога на этой экскурсии.

При создании (`201`) бэкенд рассылает уведомления (см. 1.6): `lost_alert` —
всем ищущим, кроме поднявшего; `lost_alert_searching` — потерявшемуся, если
тревогу поднял не он.

Ошибки:

| Код | `detail` | Когда |
|---|---|---|
| 404 | `Экскурсия не найдена` | нет такой экскурсии |
| 409 | `Потеряться можно только во время прогулки группы` | статус не `walking` |
| 409 | `Краевед ведёт группу — ему «Я потерялся» не нужно` | краевед жмёт «Я потерялся» за себя |
| 403 | `Сначала отметьтесь у краеведа — встряхните телефоны рядом` | я не участник группы и не краевед |
| 403 | `Искать можно только членов своей семьи` | «Не вижу …» не краевед и не член семьи |
| 404 | `Этого человека нет в группе` | `lost_user_id` не участник группы (или это краевед) |
| 422 | стандартная ошибка валидации | кривые координаты, `message` длиннее 200 |

#### `GET /lost-alerts/active` — мои открытые тревоги

Ответ `200`: `LostAlert[]` — открытые тревоги, где я потерявшийся или ищущий.
Новые первыми. Нет тревог — `[]`. Мобилка опрашивает эту ручку раз в
10 секунд, пока приложение открыто и человек вошёл.

#### `GET /lost-alerts/{alert_id}` — тревога целиком

Ответ `200`: `LostAlert` в любом статусе, в том числе закрытая: по ней экран
показывает «Нашлись». Мобилка опрашивает раз в 3 секунды, пока открыт экран
тревоги.

| Код | `detail` | Когда |
|---|---|---|
| 404 | `Поиск не найден` | нет такой тревоги |
| 403 | `Этот поиск видят только семья и краевед` | я не потерявшийся, не ищущий и не администратор |

#### `POST /lost-alerts/{alert_id}/respond` — «Иду»

Тела нет. Ответ `200`: `LostAlert`, где у меня `responding = true`. Повторный
вызов ничего не меняет и уведомлений не шлёт. При **первом** отклике
потерявшемуся уходит `lost_alert_responding`.

| Код | `detail` | Когда |
|---|---|---|
| 404 | `Поиск не найден` | |
| 403 | `Откликнуться могут только семья и краевед` | я не ищущий (в том числе я сам потерявшийся) |
| 409 | `Поиск уже закрыт` | статус не `active` |

#### `POST /lost-alerts/{alert_id}/resolve` — «Нашлись»

Тела нет. Ответ `200`: `LostAlert` со `status = "found"`, `resolved_at`,
`resolved_by`. Всем участникам поиска, кроме нажавшего (потерявшемуся и
ищущим), уходит `lost_alert_closed`. Уже `found` — `200` без изменений и без
уведомлений.

| Код | `detail` | Когда |
|---|---|---|
| 404 | `Поиск не найден` | |
| 403 | `Закрыть поиск могут только семья, краевед и тот, кого ищут` | |
| 409 | `Поиск уже закрыт` | статус `cancelled` или `expired` |

#### `POST /lost-alerts/{alert_id}/cancel` — «Отбой, я не потерялся»

Тела нет. Ответ `200`: `LostAlert` со `status = "cancelled"`. Остальным
участникам поиска уходит `lost_alert_closed`. Уже `cancelled` — `200` без
изменений.

| Код | `detail` | Когда |
|---|---|---|
| 404 | `Поиск не найден` | |
| 403 | `Отменить поиск может тот, кого ищут, или тот, кто его начал` | |
| 409 | `Поиск уже закрыт` | статус `found` или `expired` |

### 1.5. Что меняется в существующих ручках

**`GET /excursions/{id}/walk`**: у каждого элемента `members[]` новое поле
`lost_alert_id` — id открытой тревоги, где этот человек потерявшийся, иначе
`null`. По нему карта группы рисует его красным.

```json
{ "user_id": "…", "is_guide": false, "is_me": false, "lat": 53.27, "lon": 36.57,
  "accuracy_m": 12.0, "updated_at": "2026-09-26T10:15:03Z", "lost_alert_id": "5f0c7a2e-…" }
```

**`POST /excursions/{id}/walk/finish`** и **`POST /excursions/{id}/cancel`**:
`409` при открытой тревоге (правило 3 в 1.2).

### 1.6. Уведомления

`payload` у всех видов тревоги: `{"alert_id": "…", "excursion_id": "…"}`.
`{Имя}` — `display_name` потерявшегося, `{Кто}` — того, кто действовал.
Кавычки-ёлочки обязательны: имена не склоняем, «Маша» в кавычках читается
верно в любом падеже.

| `kind` | Кому | `title` | `body` |
|---|---|---|---|
| `lost_alert` (`kind = self`) | ищущим | `Потерялся участник: {Имя}` | `Нажмите, чтобы увидеть на карте, где сейчас «{Имя}», и проложить маршрут.` |
| `lost_alert` (`kind = reported`) | ищущим, кроме поднявшего | `Ищем участника: {Имя}` | `{Кто} не видит «{Имя}» рядом. Откройте карту — там последняя известная точка.` |
| `lost_alert_searching` | потерявшемуся, если тревогу поднял не он | `Вас ищут` | `{Кто} не видит вас рядом. Оставайтесь на месте — к вам уже идут.` |
| `lost_alert_responding` | потерявшемуся, при первом «Иду» каждого ищущего | `{Кто} идёт к вам` | `Оставайтесь на месте, если можете. На карте видно, где «{Кто}».` |
| `lost_alert_closed` (`found`) | всем участникам поиска, кроме нажавшего | `Нашлись!` | `Поиск участника «{Имя}» закрыт — все вместе.` |
| `lost_alert_closed` (`cancelled`) | всем участникам поиска, кроме нажавшего | `Отбой тревоги` | `Участник «{Имя}» не потерялся — поиск отменён.` |

У `lost_alert_closed` в `payload` дополнительно `"status": "found"` или `"cancelled"`.

## 2. Рейтинг краеведов

### 2.1. Что уже есть и не меняется

- `POST /excursions/{id}/rating` `{rating: 1..5, comment: ""}` — оценить
  завершённую экскурсию (только отметившийся участник, не сам краевед).
- `GET /excursions/{id}/rating` — оценки экскурсии.

### 2.2. Как считается место

Байесовское среднее, чтобы одна пятёрка не обгоняла сорок оценок по 4,8:

```
score = (C × m + сумма оценок краеведа) / (C + число оценок краеведа)
C = 5    — «вес» общего среднего
m        — среднее всех оценок всех краеведов за тот же период
```

Сортировка: `score` по убыванию, при равенстве — больше оценок, потом свежее
последняя оценка, потом `guide_id` по алфавиту. Места идут подряд без
дележа: 1, 2, 3… В рейтинг попадают только краеведы, у которых за период есть
хотя бы одна оценка.

Периоды: `all` — за всё время, `month` — оценки за последние 30 дней
(скользящее окно от «сейчас», не календарный месяц).

### 2.3. `GET /guides/rating` — таблица краеведов (публичная)

Параметры: `period` = `all` (по умолчанию) или `month`; `limit` 1–100, по
умолчанию 50; `offset` ≥ 0, по умолчанию 0. С токеном у своей строки
`is_me = true`.

Ответ `200`:

```json
{
  "period": "all",
  "global_average": 4.62,
  "prior_weight": 5,
  "total": 12,
  "items": [
    {
      "place": 1,
      "guide_id": "0a1b2c3d-3333-4a4a-9b9b-000000000003",
      "display_name": "Анна Сергеевна",
      "avatar_url": null,
      "city": "Орёл",
      "is_verified": true,
      "average": 4.9,
      "count": 23,
      "score": 4.834,
      "excursions_led": 12,
      "last_rated_at": "2026-09-25T18:02:11Z",
      "is_me": false
    }
  ]
}
```

| Поле | Что значит |
|---|---|
| `total` | сколько краеведов в рейтинге за период всего (для «ещё N» и «3-е место из 12») |
| `global_average` | `m` из формулы, 2 знака; нет оценок — `0` и `items: []` |
| `average` | обычное среднее, 2 знака — его показываем звёздами |
| `score` | байесовское, 3 знака — только для порядка, людям не показываем |
| `excursions_led` | сколько экскурсий краевед довёл до конца (`finished`) **за всё время**, в любом периоде |
| `display_name`/`avatar_url`/`city`/`is_verified` | из профиля; нет профиля — `"Краевед"`, `null`, `""`, `false` |

`422` — `period` не `all`/`month` или `limit` вне 1–100.

### 2.4. `GET /guides/{guide_id}/rating` — карточка краеведа (публичная, расширена)

Старые поля (`guide_id`, `average`, `count`, `recent`) остаются как были — на
них завязан веб. Добавляются новые. Всё считается за всё время.

```json
{
  "guide_id": "0a1b2c3d-3333-4a4a-9b9b-000000000003",
  "average": 4.9,
  "count": 23,
  "recent": [
    {
      "id": "…",
      "excursion_id": "…",
      "guide_id": "0a1b2c3d-3333-4a4a-9b9b-000000000003",
      "rater_id": "…",
      "rating": 5,
      "comment": "Рассказывала так, что дети слушали час",
      "created_at": "2026-09-25T18:02:11Z",
      "rater_name": "Ирина",
      "rater_avatar_url": null,
      "excursion_title": "Мценск: первогвардейцы и освобождение города"
    }
  ],
  "score": 4.834,
  "place": 1,
  "total_ranked": 12,
  "excursions_led": 12,
  "distribution": { "1": 0, "2": 0, "3": 1, "4": 1, "5": 21 },
  "profile": {
    "display_name": "Анна Сергеевна",
    "avatar_url": null,
    "city": "Орёл",
    "role": "local_historian",
    "is_verified": true
  }
}
```

| Поле | Что значит |
|---|---|
| `recent` | последние 20 оценок, новые первыми; `rater_name` — `"Участник экскурсии"`, если профиля нет |
| `score`, `place` | `null`, если оценок нет |
| `total_ranked` | сколько краеведов в рейтинге за всё время |
| `distribution` | сколько оценок каждого балла; ключи всегда все пять, строками |
| `profile` | `null`, если профиля нет или `user_service` не ответил |

Краевед без единой оценки — `200` с `average: 0`, `count: 0`, `recent: []`,
`score: null`, `place: null`. `404` эта ручка не отдаёт.

### 2.5. `GET /excursions?guide_id=…` — экскурсии краеведа (новый фильтр)

К существующей ручке добавляется необязательный параметр `guide_id`. С
`upcoming_only=true` (по умолчанию) — ближайшие экскурсии этого краеведа:
запись, сбор или прогулка. Ответ прежний: `Excursion[]`.

### 2.6. Уведомление «Оцените экскурсию»

Когда экскурсия переходит в `finished` любым путём (краевед завершил прогулку,
закрыл сбор или вышел срок), всем отметившимся участникам уходит:

| `kind` | `title` | `body` | `payload` |
|---|---|---|---|
| `rate_excursion` | `Как прошла экскурсия?` | `Оцените «{название}» — по оценкам другие выбирают, к кому идти.` | `{"excursion_id": "…"}` |

## 3. Изменения в `user_service` (мобилка их не вызывает)

- `GET /internal/family/{user_id}` с заголовком `X-Internal-Key` →
  `{"user_id": "…", "member_ids": ["…", "…"]}`. Нужен `search_hq`, чтобы
  понять, кому слать тревогу.
- `GET /profiles/batch?ids=a,b,c` (публичная, уже есть): в каждом элементе
  добавляется поле `city` (строка, может быть `""`).
