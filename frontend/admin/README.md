# Панель администратора — веб-приложение

Отдельное SPA на Vue 3. Ходит **только** в `admin_service` (порт 8010) и ничего
не знает про публичные сервисы платформы.

## Запуск

```bash
cd frontend/admin
npm install
cp .env.example .env.local     # если admin_service не на 127.0.0.1:8010
npm run dev
```

Откроется на <http://localhost:5173> — порт зафиксирован (`strictPort`), потому
что он прописан в `CORS_ORIGINS` у `admin_service`. Если порт занят, поменяйте
его и там, и в `vite.config.ts`.

Бэкенд должен быть поднят:

```bash
cd backend/admin_service && uv run uvicorn main:app --reload --port 8010
```

| Команда             | Что делает                          |
| ------------------- | ----------------------------------- |
| `npm run dev`       | дев-сервер с HMR                    |
| `npm run typecheck` | `vue-tsc --noEmit`                  |
| `npm run build`     | типы + прод-сборка в `dist/`        |
| `npm run preview`   | локальный просмотр собранного `dist`|

## Стек

Vue 3 (`<script setup>`, TypeScript) · Vite · Pinia · Vue Router · Tailwind CSS 3.

Внешних UI-библиотек нет намеренно: макет из Google Stitch — плоский Tailwind,
и своя тонкая прослойка компонентов ложится на него точнее, чем чужая тема.
График нарисован инлайновым SVG, иконки — Material Symbols со шрифтового CDN.

## Дизайн-токены

`tailwind.config.js` — это **перенесённый без изменений** конфиг из экспорта
Stitch: те же цвета, отступы, шрифтовые роли и размеры. Новый цвет или размер
добавляется туда, а не в компонент. Произвольных `#hex` и `px` в разметке нет.

Дополнительно к экспорту заведены три токена статусов из UI-кита: `verified`
(#2f6b45), `verified-container`, `unverified`.

Шрифты: Oswald (заголовки), Work Sans (интерфейс), Noto Serif (имена бойцов и
цитаты), Space Mono (архивные шифры, координаты, идентификаторы).

## Структура

```
src/
├── api/
│   ├── client.ts       fetch-обёртка: токены, авто-refresh при 401, ApiError
│   ├── endpoints.ts    по группе на раздел: auth / dashboard / ops / accounts / audit
│   └── types.ts        зеркало pydantic-схем admin_service
├── stores/auth.ts      сессия, двухшаговый вход, роль и политика 2FA
├── router/index.ts     маршруты + guard; пункты меню объявлены в `meta.nav`
├── composables/        useResourceList — список с пагинацией и тремя состояниями
├── components/         AppShell, StatTile, StatusBadge, StateBlock,
│                       PaginationBar, ModalDialog, TrendChart, PageHeader
└── views/              по экрану на раздел
```

Два принципа, на которых держится остальное:

1. **Меню строится из роутов.** `meta.nav` — единственный источник; добавили
   роут — пункт появился сам, удалили — исчез. Ссылок на несуществующие
   страницы не бывает по построению.
2. **Три состояния обязательны.** Любой список обёрнут в `StateBlock`:
   загрузка (скелетон), ошибка (с кнопкой «Повторить»), пусто. Happy path
   отдельно не рисуется.

## Как устроен вход

Повторяет двухшаговую схему бэкенда:

1. `POST /admin/auth/login` — почта и пароль. Если 2FA включена, ответ содержит
   только короткоживущий `mfa_token`, токенов доступа в нём нет.
2. Экран кода: шесть полей с автопереходом фокуса и вставкой из буфера целиком.
   Переключатель на код восстановления — там же.
3. `POST /admin/auth/login/mfa` — обмен на пару токенов.

Если политика `REQUIRE_TOTP=true`, а второй фактор ещё не настроен, guard
уводит на `/setup-2fa` и не пускает дальше: бэкенд всё равно ответит 403, и
водить администратора по пустым экранам незачем.

Токены лежат в `localStorage`. При 401 клиент один раз обновляет пару и
повторяет запрос; параллельные запросы ждут одного общего обновления, а не
запускают своё. Если обновиться не удалось — сессия сбрасывается и роутер
уводит на вход.

**QR-кода на экране настройки 2FA нет.** Отдавать TOTP-секрет во внешний
сервис генерации картинок нельзя, а тащить зависимость ради одной картинки не
хотелось: показывается сам ключ группами по четыре символа и `otpauth://`-ссылка
для менеджеров паролей — ручной ввод поддерживают все аутентификаторы. Если
QR нужен, добавьте `npm i qrcode @types/qrcode` и отрисуйте
`otpauth_uri` в `<canvas>` на `TotpSetupView`.

## Роли

`viewer` видит всё, но все кнопки изменения ему заблокированы, а в боковой
панели висит явная плашка «режим наблюдателя». Раздел «Администраторы» доступен
только `superadmin` — и роутом, и меню.

Это дублирование серверной проверки, а не замена ей: бэкенд отвечает 403
независимо от того, что нарисовано на клиенте.

## Экраны

| Раздел                    | Что делает                                              |
| ------------------------- | ------------------------------------------------------- |
| Обзор                     | 6 плиток KPI, график за 7/30/90 дней, состояние сервисов, хвост журнала |
| Пользователи и роли       | поиск, смена роли, блокировка с обоснованием            |
| Модерация заявок          | очередь народного архива, подтверждение и отклонение с обязательной ссылкой на источник |
| Точки «Последнего боя»    | смена статуса с основанием                              |
| Отряды и сборы            | три вкладки: потребности, отряды, выезды                |
| Маршруты                  | публикация и снятие с публикации                        |
| «Живое фото»              | очередь генерации, перезапуск, снятие с публикации      |
| Журнал аудита             | фильтры, раскрытие строки с диффом изменения            |
| Администраторы            | учётки, роли, сброс 2FA (только `superadmin`)           |
| Моя безопасность          | пароль, коды восстановления, завершение всех сессий     |

Недоступный сервис не ломает дашборд: его плитки показывают прочерк и надпись
«Сервис недоступен», а сверху появляется предупреждение со списком.

## Чего в интерфейсе намеренно нет

Три экрана из макета Stitch не сделаны, потому что за ними нет бэкенда:

- **«Источники и импорт»** — нужен `ingest_service` с парсингом Книг Памяти.
  Дашборд показывает его в блоке «Ещё не реализовано».
- **Наградной комитет** — знаки, баллы и рейтинг участников.
- **Бан со сроком** (7 / 30 дней / бессрочно) — в `auth_service` пока только
  булев флаг доступа. Основание блокировки уже собирается и пишется в аудит,
  срок появится вместе с полем `banned_until`.

Рисовать их «вхолостую» на моках не стал: на защите такой экран сразу
раскрывается вопросом «а покажите, как это работает».

## Состояние сборки

`npm run typecheck` и `npm run build` проходят: 75 модулей, ~45 КБ gzip,
роуты разбиты на отдельные чанки за счёт ленивых импортов.

Вьюхи грузятся по требованию, поэтому вход и дашборд не тянут за собой код
остальных девяти экранов.
