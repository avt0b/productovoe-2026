# Интеграция фронтенда с бэкендом — журнал

Правило проекта: **бэкенд (`backend/`) не меняется ни при каких условиях.**
Все адаптации — только во фронтенде (`frontend/web/`): прокси Vite, API-клиенты,
формы модулей подстраиваются под реальные схемы и ограничения сервисов.

Локальный запуск бэкенда: PostgreSQL 18 (`localhost:5432`, роль `postgres`/`postgres`,
базы `auth`, `users`, `map`, `search_hq`, `archive`, `routes`, `media`, `admin` —
созданы вручную, `CREATE ROLE marshruty ...` тоже выполнен про запас под будущие
сервисы, которые могут требовать именно эту роль). Каждый сервис — `uv sync` →
`cp .env.example .env` → `uv run uvicorn main:app --port <порт>`.

Ни один backend-сервис не поднимает CORS (в коде нет `CORSMiddleware`). Раз
менять бэкенд нельзя — обходим через **прокси dev-сервера Vite**
(`frontend/web/vite.config.js` → `server.proxy`): браузер обращается только к
`localhost:5173/api/<service>/...`, Vite сам проксирует на реальный порт сервиса.
Для продакшен-сборки (без dev-сервера) это не решение — там понадобится
реверс-прокси перед сервисами или CORS на их стороне; это уже не в зоне
фронтенда и оставлено как есть.

## Push 1 — auth_service (порт 8001)

**Статус: подключено полностью, работает.**

### Что сделано
- Поднят `auth_service` локально (PostgreSQL, `uv sync`, `.env` из примера без
  правок — дефолтный `DATABASE_URL` уже указывает на `postgres:postgres@localhost/auth`,
  что совпадает с локальной инсталляцией).
- `frontend/web/vite.config.js`: добавлен `server.proxy['/api/auth'] → 127.0.0.1:8001`
  (обрезает префикс `/api`, дальше путь как в сервисе: `/auth/register` и т.д.).
- `shared/utils/httpClient.js` — маленький fetch-wrapper: JSON, `Authorization:
  Bearer`, парсинг ошибок FastAPI (`{"detail": "..."}"`) в `ApiError`.
- `modules/auth/api.js` — тонкие обёртки над `/auth/register`, `/login`,
  `/refresh`, `/logout`, `/me`.
- `modules/auth/session.js` — реактивное состояние сессии (`accessToken`,
  `refreshToken`, `user`), персист в `localStorage`, восстановление сессии при
  перезагрузке (`GET /auth/me` по сохранённому токену). Экспортирован как
  `useAuthSession()` из публичного `modules/auth/index.js` — это единственная
  точка, через которую остальной фронтенд узнаёт, кто залогинен (по правилам
  Lego-архитектуры: наружу модуль торгует только через `index.js`).
- `modules/auth/roles.js` — карта реальных значений `enum Role` бэкенда
  (`family / searcher / local_historian / mentor / moderator`) → человеко-читаемые
  подписи.
- `LoginForm.vue`, `RegisterForm.vue` — реальные вызовы вместо `setTimeout`-заглушки.
- `App.vue` и `AppSidebar.vue` — шапка показывает реальный e-mail/роль
  залогиненного пользователя, «Сменить аккаунт» реально дёргает `/auth/logout`
  и чистит сессию, если пользователь был залогинен.

### Что пришлось адаптировать во фронтенде (не в бэке)
- **Вход по e-mail, не по телефону.** Бэкенд (`LoginRequest.email: EmailStr`)
  принимает только e-mail. Поле «Телефон или e-mail» в `LoginForm` переименовано
  в просто «E-mail», плейсхолдер телефона убран — иначе форма врала бы, что
  вход по телефону поддерживается.
- **Роли при регистрации** — заменил произвольные `researcher/historian/family`
  на реальные значения `enum Role` бэкенда (`family, searcher, local_historian,
  mentor`; `moderator` скрыт из публичной формы — выдаётся из админки, не
  предназначена для самостоятельной регистрации).
- **Пароль ≥ 8 символов** — добавлена клиентская проверка под
  `Field(min_length=8)` в `UserRegister`, чтобы не ловить сырой `422` от API.
- **Поле «ФИО» пока никуда не уходит.** У `auth_service` нет профиля с именем —
  это будет на стороне `user_service` (следующий кандидат). Поле оставлено в
  форме (заранее для UX), подписано «появится в профиле позже», но в API не
  отправляется — честно, чтобы не выглядело как рабочее поле, которое втихую
  игнорируется.
- **Регистрация не логинит автоматически** — `POST /auth/register` возвращает
  только профиль (`201`), без токенов. `session.register()` во фронтенде сам
  вызывает `login()` следующим шагом, чтобы для пользователя это выглядело
  одним действием.

### Что НЕ подключено (и почему)
- **VK / Яндекс ID / Госуслуги (`SocialLogin.vue`)** — в `auth_service` этого
  нет вообще (см. `backend/auth_service/README.md`, раздел «Дальше»: OAuth
  заявлен как будущая работа). Кнопки остались как локальная демо-симуляция
  (не ходят в сеть) — трогать нечего, пока бэкенд не появится.
- **«Забыли пароль»** — эндпоинта восстановления пароля в `auth_service` нет.
  Ссылка в форме ведёт в никуда, оставлена как есть до появления ручки.

### Проверено вручную
- `POST /api/auth/register` → `201`, реальная запись в Postgres (`auth` DB).
- Повторная регистрация тем же e-mail → `409 {"detail": "Пользователь с таким
  email уже зарегистрирован"}`.
- `POST /api/auth/login` → пара токенов, `GET /api/auth/me` с `Bearer` → профиль.
- Через прокси `localhost:5173/api/auth/...` — идентично прямому обращению к
  `127.0.0.1:8001`, `npm run build` и `npm run lint` чистые.
