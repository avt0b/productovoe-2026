# Архитектура проекта: модульность (принцип «Лего»)

Главное правило проекта: любую фичу можно целиком вынести в другой проект простым
копированием папки, и в этот проект можно так же просто подключить чужой модуль.
Дерево `src/` всегда должно оставаться понятным без объяснений.

## Структура

```
src/
  main.js                 # точка входа (не трогать без необходимости)
  app/                    # "корень сборки" — не модуль, а оболочка приложения
    App.vue               # корневой компонент (layout, header, RouterView)
    router.js             # собирает роуты всех модулей в один router
    components/            # компоненты самой оболочки (не бизнес-фичи)
    styles/                # глобальные стили
    assets/                # ассеты оболочки (лого и т.п.)
  modules/                # фичи — самодостаточные "кубики"
    <feature>/
      index.js             # ПУБЛИЧНОЕ API модуля — единственная точка входа снаружи
      routes.js             # роуты этого модуля (относительные импорты, только внутрь себя)
      <Feature>View.vue
      components/           # компоненты, приватные для модуля
      composables/          # (по мере надобности) логика модуля
  shared/                  # переиспользуемое и business-agnostic
    components/
    composables/
    utils/
```

## Правила

1. **Модуль = папка в `src/modules/`.** Всё, что относится к фиче (компоненты, роуты,
   composables, стили), лежит внутри неё. Между файлами внутри модуля — только
   относительные импорты (`./`, `../`).

2. **Наружу модуль торгует только через `index.js`.** Другой код (другие модули, `app/`)
   импортирует модуль как `@modules/<feature>`, а не лезет во внутренние файлы вроде
   `@modules/<feature>/components/X.vue`. Если что-то нужно наружу — экспортируй это
   явно из `index.js`.

3. **`shared/`** — только генерик-код без знания о конкретной фиче (UI-кит, утилиты,
   переиспользуемые composables). Ничего специфичного для одного модуля сюда не кладём.

4. **`app/`** — не модуль, а место сборки: корневой компонент, агрегатор роутов,
   глобальные стили, лэйаут. Бизнес-логика сюда не попадает.

5. **Алиасы путей** (заданы в `vite.config.js` и `jsconfig.json`):
   - `@`        → `src/`
   - `@app`     → `src/app/`
   - `@modules` → `src/modules/`
   - `@shared`  → `src/shared/`

   Кросс-папочные импорты — только через алиасы. Внутри модуля — относительные пути.

## Как добавить новую фичу

1. Создать `src/modules/<feature>/` со своими компонентами и `<Feature>View.vue`.
2. Добавить `routes.js`, экспортирующий массив роутов этого модуля (ленивая загрузка
   через `() => import('./...')`).
3. Добавить `index.js` с `export { default as routes } from './routes.js'` (и другими
   осознанными экспортами, если модуль отдаёт что-то ещё наружу).
4. В `src/app/router.js` — одна строка импорта + добавление в массив `routes`.

## Как перенести фичу в другой проект

Скопировать папку `src/modules/<feature>/` целиком (плюс те куски `shared/`, которые
она реально импортирует) — этого достаточно, лишних связей быть не должно.
