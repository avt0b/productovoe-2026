# Параллельная работа над клиентом: две стороны, ноль конфликтов

Клиента переделывают две независимые сессии. Правило одно и оно жёсткое:
**у каждого файла ровно один владелец**. Git конфликтует только там, где две
ветки правили один файл, — значит, пересечений по файлам быть не должно.

Дизайн у обеих сторон общий: [DESIGN.md](DESIGN.md). Эталон вёрстки — экран
входа `src/modules/auth/AuthPage.vue`.

Задание каждой стороны лежит рядом: [PROMPT-A.md](PROMPT-A.md) и
[PROMPT-B.md](PROMPT-B.md).

## Зоны

Пути — от `frontend/client/`.

```

```


Всё, что вне `frontend/client/` (бэкенд, `frontend/web`, `mobile/`, docker,
compose), в этой работе не трогает никто.

## Правила, которые держат ветки непересекающимися

1. **Не редактируй чужой файл. Вообще.** Даже одну строку, даже «очевидную
   опечатку». Нужна правка у соседа — пиши в отчёт, сведём после мерджа.
2. **Новые файлы — только внутри своей зоны.** Новый модуль — новая папка
   `src/modules/<имя>/` с `index.ts`; реестра модулей нет, приложение находит
   их само (`src/app/registry.ts`), поэтому новый модуль ничего не конфликтует.
3. **Вкладки нижней панели не добавляем и не переставляем.** Их пять, панель
   заполнена; `order` существующих вкладок не меняем.
4. **Имена и пути роутов не переименовываем.** Межмодульные переходы — только
   по имени роута (`router.push({ name: 'route-point', params })`), импортов из
   чужого модуля не бывает — это ломает «лего»-архитектуру.
5. **`src/core/` и `src/ui/` — read-only для стороны B.** Нужна новая функция в
   `core` — заводим её в своём модуле (`modules/<свой>/data.ts`), как уже
   сделано у всех. Нужен новый общий компонент — делаем его у себя в
   `modules/<свой>/components/` и пишем в отчёт, что его стоит поднять в `ui/`.
6. **A не ломает API общих компонентов.** Внутренности `src/ui/*` переписывать
   можно и нужно, но пропсы, слоты, события и имена — только добавлять, не
   переименовывать и не удалять: на них уже стоят экраны стороны B.
7. **Новых зависимостей нет.** `package.json` заморожен. Не хватает библиотеки —
   пишем пользователю, а не ставим.
8. **Не мерджим и не ребейзим чужую ветку по ходу работы.**

## Заранее согласованное между сторонами

- `src/ui/geo/GeoMap.vue` (владелец — A) нужен обеим сторонам. A добавляет в
  него проп `circles` (окружность радиуса вокруг точки) — он нужен стороне B
  для «в 5 км от вас обнаружено место гибели». Статусы точек B передаёт уже
  существующим `tone` у маркеров.
- Значок «Подтверждено» и наградные акценты — `tertiary`, полевое и поисковое —
  `secondary` (см. DESIGN.md). Обе стороны красят одинаково.
- Уведомления (`features/notifications`, владелец — B) уже подключены в
  `App.vue` и умеют вести на экран по имени роута. Сторона A новые виды
  уведомлений не заводит.

## Git

Обе ветки растут из одного коммита. Перед стартом текущая работа должна быть
закоммичена, иначе worktree её не увидит.

```bash
git worktree add ../client-a -b feat/client-a
git worktree add ../client-b -b feat/client-b
```

- Коммиты: `feat(client/a): …` и `feat(client/b): …`, по одному осмысленному
  коммиту на экран, а не один общий в конце.
- Перед каждым коммитом — `git status --short`: в списке не должно быть ни
  одного файла вне своей зоны. Попал чужой — откатить (`git checkout -- <файл>`).
- Порядок мерджа: **сначала A** (дизайн-система), затем B поверх неё. Мердж
  делает пользователь.
- `.claude/` не в git, поэтому у каждого worktree свой `launch.json`. Сторона A
  запускает превью по имени `client` (порт 5174), сторона B создаёт у себя
  `.claude/launch.json` с портом 5175 — два дев-сервера не должны драться за порт.

## Перед сдачей

1. `npx vue-tsc --noEmit` — без ошибок.
2. Дев-сервер, каждый свой экран открыт и проверен в браузере на 375×812 и на
   низком экране 375×667, включая состояния «загрузка», «ошибка», «пусто»,
   «без аккаунта».
3. Отчёт: что сделано по экранам, какой функционал добавлен, что осталось, что
   нужно от соседней стороны.
