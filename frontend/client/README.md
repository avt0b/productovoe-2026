# Приложение «Маршруты победы»

Приложение для семей, поисковиков и краеведов: маршруты памяти, «Последний бой»,
штаб отрядов, живые портреты героев, профиль исследователя.

Вход — по почте и паролю через `auth_service` или демо-входом без аккаунта.
Карты берут точки из `map_service` и `route_service`, остальные окна — из
заглушек в самих модулях.

## Запуск

```bash
cd frontend/client
npm install
npm run dev        # http://localhost:5174
npm run build      # проверка типов + сборка
```

Порт 5174: 5173 занят админкой, оба приложения запускаются одновременно.

Адреса сервисов и подложки карты — в `.env.local` (образец — `.env.example`).
Без него клиент идёт на локальные порты 8001–8007 этого же компьютера.
Сменить сервер можно только пересборкой: экрана выбора в приложении нет.
Для APK адреса берутся из `.env.android.local` (образец — `.env.android.example`);
сборка с `127.0.0.1` останавливается с ошибкой — на телефоне это сам телефон.
Шлюз пишется полным адресом с префиксом, как у прокси веб-версии
(`frontend/web/vite.config.js`): `VITE_USER_API_URL=https://marshruty.ru/api/users`.
Адреса считает `src/core/server.ts`.

## Шрифты и иконки — свои, не из интернета

Manrope и Material Symbols лежат в `public/fonts` и подключаются в
`src/style.css`. В APK сети может не быть, а иконки — это лигатуры: без файла
шрифта вместо значка остаётся слово («search», «person»).

Material Symbols качается **сабсетом** — только те иконки, что есть в
приложении (`scripts/icon-names.txt`, около 180 КБ вместо 4 МБ). Добавили в
разметку новую иконку — допишите её имя в список и прогоните:

```bash
sh scripts/update-fonts.sh
```

## Данные из сервисов

Запросы — `src/core/api.ts`: `apiGet('map', '/poi', { kind: 'grave' })`.

Сервис **не ответил** (нет сети, сервер не запущен, таймаут 6 с) — экран
показывает демо-набор своего модуля и плашку `<DemoDataBadge>`:

```ts
return withDemoFallback(loadFromServices, () => DEMO)
```

Так карта работает и без бэкенда — на защите, в APK без сети. Если сервис
**ответил ошибкой**, демо её не прячет: экран показывает ошибку с повтором.
После отказа сервис полминуты считается недоступным, чтобы следующий экран не
ждал таймаут заново.

Наполнить сервисы демо-точками Орловской области —
`uv run python -m scripts.seed_orel` в `backend/map_service` и
`backend/route_service`.

## Карта

`<GeoMap>` из `src/ui/geo` — Leaflet с подложкой OpenStreetMap.
Окно отдаёт метки, линии и своё местоположение пропсами:

```vue
<GeoMap
  v-model:selected="selectedId"
  :markers="[{ id, lat, lon, label, icon: 'star', tone: 'primary' }]"
  :paths="[{ id, points, tone: 'secondary', dashed: true }]"
  :user="geo.position.value"
  :locating="geo.status.value === 'locating'"
  class="h-96"
  @locate="geo.start"
/>
```

- **Цвет метки — роль палитры** (`primary`, `secondary`, `tertiary`,
  `neutral`), не hex: метки рисуются классами Tailwind, линии — `stroke-*`.
- **Геолокация — `useGeolocation()`** из `src/core/geo`. Разрешение
  спрашивается только по кнопке «Где я», а не при открытии карты.
- **Подложка** меняется в `.env.local` (`VITE_MAP_TILES_URL` и подпись
  правообладателей). По умолчанию — тайлы OpenStreetMap: их правила
  разрешают умеренную нагрузку, на хакатон и демо хватит; для прода — свой
  тайл-сервер или договор с 2ГИС. Бесплатные тайлы CARTO без ключа рисуют
  поверх карты «API KEY REQUIRED».
- **Движок** спрятан в одном компоненте: переход на MapLibre или 2ГИС не
  затронет окна.

## Стек

Vue 3 (`<script setup>`, TypeScript strict) · Vite · Pinia · Vue Router ·
Tailwind CSS. Тот же набор, что у админки, — чтобы переходить между ними без
переучивания. UI-библиотеки нет: вёрстка макета Stitch переносится классами
Tailwind почти один в один.

## APK (Android)

Обёртка — Capacitor 8: та же сборка Vite внутри Android WebView, код окон не
меняется.

```bash
cd frontend/client
cp .env.example .env.android.local   # адреса сервисов — IP компьютера в локальной сети
npm run android:ar                   # собрать AR-модуль из mobile/ (можно пропустить)
npm run android:sync                 # сборка с .env.android.local и копирование в android/
cd android
./gradlew assembleDebug              # app/build/outputs/apk/debug/app-debug.apk
```

Нужны Android SDK (`ANDROID_HOME` или `android/local.properties`) и JDK 21+
(подойдёт JBR из Android Studio). За прокси Gradle нужны
`-Dhttps.proxyHost=… -Dhttps.proxyPort=…`. Открыть проект в Android Studio —
`npm run android:open`.

- **Gradle 9.5 — не выше и не ниже.** Шаблон Capacitor собран на AGP 8.13:
  Gradle 9.6 удалил внутренний API, на который опирается AGP 8, а Gradle 8.14
  из шаблона не запускается на Java 25 из свежей Android Studio. Поднимать
  вместе с переходом Capacitor на AGP 9.
- **Сервисы по http в локальной сети.** Если адреса в `.env.android.local`
  начинаются с `http://`, приложение открывается с `http://localhost`, иначе —
  с `https://localhost` (оба origin есть в CORS сервисов). На https-странице
  WebView пропускает к http-сервисам запросы API, но блокирует картинки, аудио
  и видео из MinIO («Mixed Content… blocked») — аватарка сохранялась, но не
  показывалась. Смена схемы — смена origin: после такой пересборки войти
  придётся заново. `cleartext` и `allowMixedContent` в `capacitor.config.ts`
  — для того же стенда; в проде — https и эти флаги убрать.
- **Телефон должен достучаться до компьютера:** сервисы запускаются с
  `--host 0.0.0.0`, брандмауэр пропускает порты 8003 и 8006, телефон в той
  же сети. Не достучался — приложение покажет демо-данные с плашкой.
- **Геолокация** — разрешения `ACCESS_FINE_LOCATION` и
  `ACCESS_COARSE_LOCATION` в манифесте; система спрашивает их по кнопке
  «Где я».
- **AR** — нативный модуль из [`mobile/`](../../mobile/): камера, компас,
  ARCore. `npm run android:ar` собирает его в AAR
  (`mobile/ar/build/repo`), дальше APK подключает готовый AAR. Отдельной
  сборкой — потому что AR собран на AGP 9, а шаблон Capacitor на AGP 8:
  двух версий AGP в одной сборке Gradle не бывает. Не собрали AAR — APK
  соберётся без AR, а кнопка «Запустить AR-поиск» скажет об этом.
  С AR приложение весит ~33 МБ (ARCore и Filament) и требует Android 8.0.
- **Модель проводника** в репозиторий не кладём (чужая лицензия). Положите
  свою в `mobile/ar/src/main/assets/companion/` — мост возьмёт первую
  найденную `.glb`. Нет модели — экран работает без проводника.
- **NFC** — разрешение `NFC` и `uses-feature` с `required="false"`: на
  телефонах без NFC приложение ставится и работает. Метка с нашей ссылкой
  (`marshruty://nfc…`) открывает приложение и когда оно закрыто.

## NFC-метки

Задумка: на табличке у памятника или на точке маршрута висит метка — человек
подносит телефон и попадает сразу на нужный экран, не ища точку на карте.

Пока это самостоятельный кусок:

- механика — `src/features/nfc` (нативный плагин `MarshrutyNfc`,
  `useNfcScanner`, окно «что на метке»);
- экран — модуль `src/modules/nfc` (`/nfc`), вкладки у него нет: временный
  вход — иконка NFC в шапке, она появляется, только если модуль подключён;
- метки читаются, пока экран открыт (режим чтения Android работает только у
  активного экрана). Метка, которой открыли приложение, ждёт на этом экране.
- экран умеет **записывать** метки: ссылку на экран приложения
  (`marshruty://routes/<точка>?route=<маршрут>`), обычную ссылку или текст —
  чтобы подготовить таблички самим, без сторонних приложений.

Прикрутить к окнам: звать `useNfcScanner` там, где нужно ловить метки, или
открывать экран `{ name: 'nfc' }` с проверкой `router.hasRoute('nfc')`.
NFC есть только в APK — в браузере экран честно говорит об этом.

## Модули — как добавить или убрать окно

Каждое окно — папка в `src/modules/`:

```
src/modules/hq/
├── index.ts          описание модуля: роуты и вкладка
├── HqPage.vue        экран
├── data.ts           заглушка данных (потом — запросы к сервису)
└── components/       то, что нужно только этому окну
```

```ts
// src/modules/hq/index.ts
import { defineModule } from '@/core/module'

export default defineModule({
  id: 'hq',
  tab: { title: 'Штаб', icon: 'volunteer_activism', route: 'hq', order: 30 },
  routes: [
    {
      path: '/hq',
      name: 'hq',
      component: () => import('./HqPage.vue'),
      meta: { title: 'Штаб' },
    },
  ],
})
```

- **Добавить окно** — положить папку. Приложение найдёт её само
  (`src/app/registry.ts`, `import.meta.glob`), общего списка править не нужно.
- **Убрать окно** — удалить папку или выставить `enabled: false`.
- **Порядок вкладок** — `tab.order`, шаг 10, чтобы новый раздел вставал между
  соседями.

Центрального списка модулей нет намеренно: окна делаются отдельными PR, и общий
файл со списком конфликтовал бы в каждом из них.

Модули не импортируют друг друга. Общее — только из `src/core`, `src/ui` и
`src/features`. Ссылка на экран другого модуля — по имени роута
(`{ name: 'profile' }`) с проверкой `router.hasRoute`: нет модуля — нет ссылки,
а не падение.

### Фичи — механики, которые встраивают окна

`src/features/<фича>/` — самостоятельная механика со своей логикой, текстами и
экраном: окно её встраивает, но внутрь не лезет. Снаружи доступно только то,
что экспортирует `index.ts` фичи. Править механику — значит править её папку,
окна при этом не трогаются.

- **`features/bump`** — бамп: датчик тряски (`useShake`), встряска на сервер и
  разбор ответа (`useBump`), экран тряски (`BumpPad`), анимация «Вы вместе!»
  (`TogetherOverlay`). Окно «Экскурсии» отдаёт ей id экскурсии, роль и место
  человека — и показывает, что она вернула.
- **`features/point-route`** — карточка точки и маршрут до неё. Нажатие на
  метку разворачивает карту, внизу — `PointSheet` с тем, что это за место, и
  кнопкой «Начать маршрут»: `usePointRoute` сам спрашивает геолокацию, строит
  путь через OSRM (до 5 км — пешком, дальше — на машине), перестраивает его по
  ходу и говорит «Вы на месте»; тот же путь можно передать в Яндекс Карты.
  Окно заводит `usePointRoute` на свой `useGeolocation`, добавляет его `path`
  к линиям карты, отдаёт `GeoMap` проп `focus` и кладёт `PointSheet` в слот
  `sheet` (у карты — `expand-on-select`).

### Мета экрана

| Поле | Что делает |
| --- | --- |
| `layout` | `tabs` — шапка и нижняя панель (по умолчанию), `detail` — «Назад» и «Поделиться», `bare` — пустой экран |
| `title` | заголовок в шапке |
| `public` | открыт без входа |
| `auth` | это экран входа; нет такого экрана ни в одном модуле — приложение открыто всем |
| `tab` | какую вкладку подсвечивать на вложенном экране |

## Вход

Сессия — `src/core/session`. Экраны зовут `useSessionStore().signIn(...)` и не
знают, откуда берётся пользователь. Провайдер — `serviceAuthProvider`:

- **Почта и пароль** → `auth_service`: регистрация (`/auth/register`, при
  регистрации можно выбрать роль краеведа), вход, пара JWT-токенов.
  access-токен живёт 15 минут; `api.ts` при ответе 401 один раз обновляет его
  через `/auth/refresh` и повторяет запрос.
- **Госуслуги / VK ID / MAX** → ручки `auth_service` `/auth/external/*`
  (`core/session/externalAuth.ts`). Кнопки берут из `/auth/external/providers`,
  что включено на сервере; тестовый провайдер помечен «тест». VK ID и
  Госуслуги возвращают человека в приложение: в браузере на `/auth/external`,
  в APK — ссылкой `marshruty://auth/external` (intent-filter в манифесте,
  `@capacitor/app` + `core/deeplinks.ts`). MAX подтверждает вход в боте —
  экран входа сам спрашивает сервис, готово ли. Адрес возврата должен быть в
  `EXTERNAL_AUTH_RETURN_PREFIXES` у `auth_service`.
- **Пустые поля** → демо-пользователь без токена. Смотреть можно всё, писать
  в сервисы от имени человека (запись, взнос, бамп) — нет:
  `session.hasAccount === false`, экран предлагает войти.

Запрос от имени человека:

```ts
apiRequest('POST', 'hq', `/excursions/${id}/registrations`, { auth: true })
```

- **Токены лежат в localStorage** — это прототип. В проде refresh-токен
  хранится в защищённом хранилище телефона.
- **Имени в `auth_service` нет.** Имя, город и фото живут в профиле
  `user_service`: окно «Профиль» после загрузки кладёт их в сессию
  (`session.updateUser`) — оттуда их берут шапка и аватар. До первого открытия
  профиля — имя из регистрации или начало почты.
- **После входа открывается «Профиль»** — там заполняют фото, имя и «о себе».
  Если человек шёл на конкретный экран, возвращаем на него (`?next=`), а
  демо-вход остаётся на стартовой вкладке: своего профиля у него нет.
- **Сервер входа не ответил** — экран входа предлагает проверить подключение
  или оставить поля пустыми и войти в демо-режиме.
- **Какие кнопки рисовать** — `can.verifyArchive(user)`, `can.addLastStand(user)`
  и т. д. из `@/core/session`: повтор проверок ролей в сервисах, чтобы не
  показывать действие, которое закончится ответом 403. Решает всё равно сервис.

## Структура

```
src/
├── main.ts
├── App.vue              выбирает каркас по meta.layout
├── app/
│   ├── registry.ts      поиск модулей
│   ├── router.ts        роуты модулей + охрана входа
│   ├── layouts/         каркасы: с вкладками, детальный, голый
│   └── pages/           служебные экраны (нет модулей)
├── core/                без разметки: модуль, сессия, роли, сервер, загрузка, запросы, гео
├── features/            механики, которые встраивают окна: бамп (bump), маршрут до точки (point-route)
├── ui/                  общие компоненты: шапки, нижняя панель, иконка, состояния, карта,
│   │                    окно поверх экрана (SheetDialog), «нужен аккаунт» (AccountRequired)
│   └── form/            поля форм
└── modules/             окна
```

## Правила

- **Токены — в `tailwind.config.js`.** Цвета, радиусы, тени и шрифтовые роли
  перенесены из Stitch. Цвета, которые в макете стояли прямо в разметке
  (оливковая карточка выезда, нарисованная карта), получили имена там же.
- **Иконки — `<MsIcon name="..." :size="20" />`**, а не `text-[20px]`.
- **Три состояния у каждого экрана:** загрузка, ошибка с повтором, пусто —
  `useAsync` + `<StateBlock>`. Заглушки отвечают с задержкой (`withLatency`),
  чтобы эти состояния было видно уже сейчас.
- **Кириллица в шрифте обязательна** — Manrope её имеет.
